Camera 30 fps profile / 2026-10-15

Problem and evidence
  Previous sensor table wrote VTS=0x0bb8=3000; ae_set documented ~20 fps.
  HDMI uses 75 MHz / (2200*1125) = 30.303 Hz. Its OSD counter counts output
  refreshes, not distinct camera frames. video_out selects the published DDR
  read pointer every output VSYNC, even if no new camera frame is available.
  Thus 20 fps input cannot supply a distinct image on every ~30 Hz refresh.
  Existing S_dbg_frame_repeat_seen means that a second camera frame arrived;
  it is NOT a repeated-content counter and must not be interpreted as one.

Change
  Sensor 0x320e/0x320f: 0x07/0xd0 (VTS=2000), nominal full-mode 30 fps.
  Full 2592x1944 capture, HTS, PLL, scaler/crop and HDMI timing unchanged.
  Exposure default/max 3990 half-lines (~33.25 ms), minimum 3.
  Source: local SC500CS V1.8 manual pp.15 (full mode 30 fps), 21 (VTS),
  23 (half-line exposure units and maximum 2*VTS-10).
  AE, APB defaults/clamps, both MCU startups, buttons, touch slider,
  OSD bar, MCU Wi-Fi validation, local server validation/UI now agree.
  Gain default 80 and image processing parameters unchanged.
  OSD bar remains shift/add; no new frame buffers, counters or image modules.
  Prior working MCU IP/JTAG baseline and double-tap local AF are retained.

  Check picture, menu range, motion smoothness and double-tap AF in good light.
