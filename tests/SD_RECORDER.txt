板载 TF 卡延时摄影（REC1）
=========================

功能与操作
----------
将 FAT32 格式的 TF 卡插入板载卡槽。推荐先用现有的 4~32 GB SDHC 卡测试。
程序不会格式化卡，也不会覆盖已有文件；不支持 exFAT。
屏幕菜单的原“俯仰角”状态行改为“录制设置”，舵机仍可在菜单外拖动控制。
进入后：单张拍照、开始录制、停止录制、保存间隔、已保存、状态、返回。
间隔依次为 2、5、10、30、60 秒，触摸间隔左侧减少、右侧增加；按键 OK 切换。
开始/停止/拍照均可用触屏或四个物理键选择。中心自动对焦入口保留。
菜单旁小方块：暗绿色=空闲，红色=定时录制，橙色=单张写入；错误也显示红色，
详细状态请看录制页“状态”和串口 SD: ERROR 信息。

输出 640x360、24-bit RGB 彩色 BMP，文件为 T0000001.BMP、T0000002.BMP……。
每张 691254 字节，默认每两秒抓取一次；如果写入更慢则保存完成后再抓下一张，
不排队补帧。每两秒一张时约 1.24 GB/小时（十进制）。这是图片序列，不是 AVI/MP4。
图像来源为当前显示特效之后、标志和菜单叠加之前，采用每三行/列取一个像素。
因此保留颜色调整与灰度/反色/Sobel 等效果，但不录入菜单、时钟和识别框叠加。
它是最近邻抽样，细线可能有混叠；第一版没有加入会占更多资源的缩小滤波器。
显示端仍保持 1920x1080@30，不随录制分辨率降低。
RTC 日期有效、没有 OSF/总线错误时写入文件时间，否则使用 1980-01-01。
停止会完成当前照片并关闭文件。请等状态回到空闲再拔卡。
突然断电/拔卡可能留下不完整 BMP 或损坏正在更新的 FAT，尚无掉电事务保证。
SD/文件错误会停止定时录制；重新插好卡后再次点“单张拍照/开始录制”可重新初始化。
DDR 读取超时属于图像存储通路故障，需重启并排查 DDR，不能靠重新插卡解决。
用户上板已确认 SD 初始化、FAT32 挂载通过；完整 BMP 保存、实际写速与持续录制仍待验收。

硬件与数据通路
--------------
SPI mode 0，SD_CLK=A7、CMD/MOSI=A8、DAT0/MISO=E8、DAT3/CS=B12。
DAT1=D8、DAT2=A12 不作为输出驱动，未占用。SD 逻辑电平 3.3 V。
50 MHz APB 下初始化时钟 200 kHz，正常读写时钟 6.25 MHz。
初始化 CMD0/CMD8/ACMD41/CMD58，标准容量卡另发 CMD16；支持 SDSC 字节地址与 SDHC 块地址。
数据读写检查/生成 CRC16，写响应和忙等待有超时；多扇区写使用 CMD25。
文件系统来自官方 FatFs R0.15，禁用格式化、长文件名、exFAT，使用共享扇区缓冲。
来源：https://elm-chan.org/fsw/ff/arc/ff15.zip
接口参考：https://elm-chan.org/docs/mmc/mmc_e.html
许可完整保留在 FDwork/shared/fatfs/ff.c 和 ff.h 文件头。

S_edge RGB -> 3x 抽样 -> 四像素/128-bit 打包 -> 异步 FIFO -> DDR 独立快照。
DDR 用户地址单位为 2 字节，录制基址为 8000000（物理字节偏移 16000000）。
当前视频两帧区各占 6220800 字节，第二帧基址 6400000，不与录制区重叠。
每像素缓存 00RRGGBB，录制缓存 921600 字节；BMP 输出时去掉填充字节。
录制 DDR 写入只等待视频突发结束，不等视频读返回；MCU读快照前等待旧视频读返回。
MCU快照读命令发出后允许视频继续提交命令，首个返回归录制，其余归视频。
DDR桥按队首命令选择读/写ready；写入需要地址和数据两个通道同时就绪。
录制缓存直到下一次抓取请求才改变。FIFO 溢出或不完整帧使本次抓取失败。
MCU 每轮最多读取 128 个 DDR 字（512 像素），分块写文件，不申请整帧 MCU 内存。
SD 忙等待/扇区边界穿插 USB 触屏与按键处理，FatFs 不重入。

REC1 APB 基址 0x70001000
-----------------------
00: 0x52454331 能力标识。
04: 写 bit0 请求下一个完整视频帧；读 bit0=busy bit1=ready bit2=frame error。
08: 清除完成/busy，跨时钟域取消抓取并清空待写FIFO；已发出的DDR读仍接收其返回。
0c: 快照 128-bit 字数 57600。
10: 像素采集计数（诊断用，跨域采样，出错后参考）。
14: DDR诊断，28:19=未返回视频读数，18:16=录制状态机，15:0=已写快照字数。
18: 抓帧错误原因，1=FIFO满，2=视频帧提前结束。
1c: 0x00010003，DDR 命令 FIFO 复位释放握手修订号。
20: 写快照字索引 0..57599，发起异步 DDR 读。
24: bit0=读请求忙；忙消失后读取 30/34/38/3c 的四个像素。
40: SPI 半周期分频值，周期为 2*(DIV+1) 个 APB 时钟。
44: SPI CS 电平；48: 写一个发送字节；4c: bit0=busy, bits15:8=接收字节。
60: MCU 状态 -> OSD：31:16 保存数 BCD（显示末四位），14:12 间隔索引，
    10=录制菜单页，9=有保存任务，8=定时录制，7:0=错误码。

错误码（串口以十进制输出）
------------------------
0x10+FatFs返回值：挂载失败，例如 19=FR_NOT_READY，29=FR_NO_FILESYSTEM。
0x21（33）：视频帧不完整或 FIFO 溢出。
0x22（34）：等待抓取超时。
0x23（35）：DDR 读取超时。
0x30（48）：文件短写/卡空间不足；0x31（49）：七位文件序号耗尽。
0x40+FatFs返回值：创建/写入/关闭失败，例如 65=FR_DISK_ERR。
g_rec_state、g_rec_error、g_rec_saved 可在 FD 调试器查看。

抓帧错误及视频阻塞修复（sd-test-v4 + FPGA revision 00010002）
----------------------------------------------------------
上板v3已确认 SD: MOUNT OK div=3，原CRC挂载失败不再出现；
当前故障是ERROR=33及连续重试后视频变黑，菜单仍显示。
代码与仿真确认的缺陷：
1. DDR桥把写地址ready当成读命令的接收条件，读通道不ready时会丢请求。
2. 录制写入等待全部视频读返回，未返回请求可阻塞抓帧直至FIFO溢出。
3. APB取消只清MCU可见状态，没有取消像素域/DDR域任务及释放仲裁。
修复：
- 队首命令独立于enable解码，读等arready，写等awready与wready。
- 快照写入不等待视频读返回；MCU快照读仍保证返回归属。
- 错误自动撤销抓帧、清FIFO和释放视频；软件取消跨域传播。
- 已发出的快照读在取消后仍收取其返回，等待期间不阻塞新视频请求。
- 视频未返回计数防下溢；同时到达的请求与帧边界不会丢掉新请求。
- MCU错误路径先取消采集再关闭文件，错误33打印具体采集原因和计数。
- MCU拒绝在旧版FPGA上启用录制，需要同时下载本次bit和ELF。

DDR 快照读取诊断（sd-test-v5，沿用 FPGA revision 00010002）
--------------------------------------------------------
用户 v4 实测：hw=00010002、MOUNT OK，随后 ERROR=35，三次 saved=0。
35=0x23，是抓帧已报告就绪、写过 BMP 文件头后，MCU 等待快照读应答超时。
现有日志不能区分：等待视频读排空、等 DDR 接收命令、等返回或跨时钟应答异常。
此版不宣称修好了板上 DDR 故障，不修改 FPGA，不重新生成 bit。
固件改动：
- 启动标识 sd-test-v5；仍要求 hw=00010002。
- CAPTURE_READY 打印已写 DDR 字数、DDR 状态、video_pending、抓帧时间。
- DDR_READ_TIMEOUT 在取消前打印 word、ms、busy、cap、words、state、
  video_pending、before/after 原始调试寄存器值。
- DDR 等待改为 100ms 实际计时，保留异常计时器下的有限轮询保护；
  异常等待中继续服务触摸/按键，避免原固定迭代次数依赖 MCU 执行速度。
- 原错误路径取消采集、停止录制、保留未完成文件，不增加 saved。
诊断解释（仍需结合实测）：
state=0 且 video_pending 固定非零：等视频读返回排空；
state=3：等共享 DDR 命令队列 ready；state=4：已提交快照读，等数据返回；
state=0、pending=0、busy=1：需进一步查仲裁忙信号或跨域应答。
主机测试通过：70ms 延迟应答、毫秒计数回绕、首字/第130字卡住、取消重拍，
以及原完整 BMP 内容、CRC、FatFs、卡满和拔卡错误路径。

首个 DDR 视频读丢失修复（sd-test-v6 + FPGA revision 00010003）
----------------------------------------------------------
用户 v5 实测：CAPTURE_READY words=57600；DDR_READ_TIMEOUT word=0、state=0、
video_pending=1，before/after 都为 0008E100。卡在快照读发出前的视频读排空。
找到并复现的缺陷：命令 FIFO 实际 IP 内部 asy_rst0/asy_rst1 在外部复位
释放后再保持两拍；DDR 桥原 ready=!afull 却立即为真。视频首个读请求因此
被上游记账，FIFO 指针却仍在复位而不推进，永久剩余一个未返回请求。
修复只增加与真实 FIFO 同步释放的两拍门控：复位未释放不报告 ready、不入队、
不出队。没有清零或跳过 video_pending，也没有放弃读返回的归属保护。
