实际硬件
- ATK-ESP-01，ESP8266，3.3V 供电和逻辑；不是 ESP32。
- 模块 TXD -> FPGA E12（USART0 RX）。
- 模块 RXD -> FPGA E16（USART0 TX）。
- 模块 RST -> FPGA F13。
- 模块 GPIO0 -> FPGA E17。
- 用户已在 TD MCU IP 中开启 USART0；请保留其生成配置。
- USART1 / COM9 用于现有电脑日志、RTC 校时，不直接等于 ESP 下载口。
- RST/GPIO0 应默认释放、上拉高；GPIO0 在复位时为低进入下载模式。
- 编程前确认模块 Flash 容量，备份原 AT 固件；不要未经确认烧写硬件。
- Wi-Fi 密码、设备密钥仅放本地忽略的配置文件，不提交、不在日志中打印。

已经完成的共用硬件源码（尚未生成并验证 Wi-Fi bitstream）
- user_source/hdl_source/design_top_wrapper.v：USART0 接线；RST/GPIO0 开漏控制及输入同步。

传输方案（待两边共同确认，不是已经实现的接口）
- 网络使用 HTTPS；IP 访问计划由 Caddy 自建 CA 提供 TLS，ESP8266 信任该 CA，不使用 setInsecure 绕过校验。
- 当前没有服务器 SSH 访问、真实设备密钥、Wi-Fi 凭据或 CA 文件。
- 先实现连接、心跳、命令执行结果回传，再做照片分块上传。
- 串口使用有类型、序号、长度、校验的数据帧；控制和照片数据区分类型，禁止混入 Serial.print 调试文本。
- 初始串口 115200，确认可靠后再测试高波特率。
- 建议每块 512 字节，接收确认、超时重传、重复包去重；完整照片按总长度和整体校验验证。
- 服务器命令必须区分待领取、已下发、执行成功/失败；不能仅收到网络命令就报告 MCU 执行成功。
- HTTP 路径/字段、UART 帧字节布局尚未冻结。请先把你的接口建议写入 wifi/，供原对话同步；避免私自把候选协议写成已对接。
