Camera timing/profile update, 2026-10-15

The user requested higher effective camera frame rate before adding image features.
Sensor VTS is now 2000 instead of 3000. Exposure units remain half-lines.
Exposure default/max: 3990; valid range 3..3990 (previously 3..5990).
Gain remains 16..143, default 80. No UART message format or command ID changes.

MCU set_parameters rejects exposure >3990 with WF_BAD_ARGUMENT. FPGA APB and
camera AE logic independently clamp out-of-range direct writes to 3990.
Server validation and web input limits now use 3990. Already queued older
commands above this limit will fail validation at the MCU; do not replay them.
ESP firmware may keep transporting parameter values without interpretation;
if it validates the old upper bound locally, update it to 3990 in its own chat.
No files under wifi/esp8266 were edited. No deployment or flashing performed.

This supersedes only the exposure range in INTERFACE_REVIEW.txt and
MCU_BRIDGE_STATUS.txt. All replay, photo, TLS and request-only UART rules remain.
