1. 网络、认证与资源限制
- ESP 主动连接，暂定 base_url=https://101.43.33.186，端口 443。
- HTTPS 至少支持 TLS 1.2；使用提供的 CA 验证证书链、有效期和目标身份。
  IP SAN 与所选 ESP8266 Core/BearSSL 的身份匹配必须先用本地证书实测；
  如果数值 IP 校验不兼容，由原对话提供证书匹配的 DNS 名称，不关闭验证。
- Wi-Fi SSID/密码、设备 ID/密钥、CA 配置由本地忽略文件提供，不打印密钥。
  CA 公钥证书不是秘密，但绝不把 CA 私钥交给设备或提交仓库。
- 设备 API 统一 Authorization: Bearer <device_token>；令牌限定单一 device_id。
  浏览器用户认证由服务器负责，手机不持有设备令牌。
- JSON UTF-8；所有 ID 是 32 个小写十六进制字符，UART 对应原始 16 字节。
  所有 epoch 为 UTC Unix 秒；不得把北京时间直接当 epoch。
- v1 JSON 请求/响应体至多 2048 字节；服务端提供 Content-Length，
  不压缩、不返回 chunked JSON、不重定向；设备拒绝过长/畸形/缺字段响应。
  上述应用层大小限制不等于 TLS record 大小；未经协商不缩小 TLS RX 缓冲。
- 同时只发一个 HTTP 请求；心跳建议 30 秒，空闲命令轮询建议 2 秒，
  连接/请求均有截止时间，故障退避 1/2/4/8/16/30 秒并加随机抖动。
  401/403 停止业务请求并报告本地认证故障；429 遵守有上限的 Retry-After；
  网络/5xx 可重试；其他 4xx 保留错误并停止该操作，不无限重试。
- SNTP 只用于建立合理的初始证书校验时间，不视为认证时间源。
  HTTPS 验证后取服务器时间用于 RTC 更新；初始时间不可用时等待校时，
  不调用 setInsecure、不用编译时间覆盖 RTC。

2. HTTP 路径与 JSON 契约（以下全部待确认）
路径公共前缀 P=/api/v1/devices/{device_id}
统一错误：{"error":{"code":"...","message":"..."}}。
code 稳定供程序判断，message 只供显示；错误中不得包含令牌。

2.1 POST P/heartbeat -> 200
请求示例：
{"protocol":1,"boot_id":"<32hex>","firmware":"0.1.0","uptime_s":12,
 "wifi_rssi_dbm":-60,"free_heap_bytes":30000,"mcu_online":false,"mcu":null}
响应：{"protocol":1,"server_time":1791972000,"heartbeat_interval_s":30}
以上数字是示例，不表示实测结果。
mcu 为最近一次 MCU 状态对象，未连接时为 null；不得凭 ESP 在线推定 MCU 正常。
status 包括 exposure、gain、recording、interval_s、rtc_valid、sd_ready、busy；
每个未知字段用 null，附 age_ms，服务器要显示过期状态。

2.2 GET P/commands/next -> 204（无命令）或 200
200：{"command_id":"<32hex>","lease_id":"<32hex>","lease_s":120,
      "kind":"capture","args":{},"expires_at":1791972120}
每设备最多一个未完成命令；GET 领取具有服务端租约语义，禁止缓存。
已领取但未确认的命令在租约到期后可用同一 command_id 重新领取，
新领取分配新 lease_id；不得为同一动作重新分配 command_id。
kind/args 候选：
  capture           {}，单张照片保存到 SD 成功才算成功，不等待照片上传。
  set_parameters    {"exposure":3,"gain":16}，两字段必填且原子检查后应用。
                    exposure=3..5990，gain=16..143，不静默截断或 clamp。
  timelapse_start   {"interval_s":2}，候选枚举 2/5/10/30/60。
  timelapse_stop    {}。
参数单位沿用当前 MCU 原始值；interval_s 不是保证的实际保存周期。
上述枚举来自现有 anlu_app/main.c 的菜单映射；串口桥支持情况及忙时行为
由 MCU 负责人确认；不假设能每 2 秒保存一张。
首版不开放任意寄存器写入、执行脚本或远程烧录命令。

2.3 POST P/commands/{command_id}/events -> 200
请求：{"event_id":"<32hex>","lease_id":"<32hex>",
       "state":"dispatched","code":"OK","result":{}}
响应：{"accepted":true,"command_id":"<32hex>","state":"dispatched"}
同 event_id + 相同请求幂等返回原结果；不同请求复用 ID 返回 409。
状态：queued -> claimed -> dispatched -> succeeded / failed / unknown。
claimed 由服务器领取生成；dispatched 只能在 MCU COMMAND_ACK 接受后生成；
succeeded/failed 必须来自 MCU RESULT 或明确的前置验证失败。
unknown 表示已可能执行但结果丢失，禁止把网络超时或 MCU 重启报告成成功。
active 命令每 30 秒重发有新 event_id 的当前状态以续租；终态不可回退。
延迟事件不能把终态覆盖为 dispatched；过期 lease 返回 409 后重新协调状态。
结果上传失败时保留结果并重试；结果确认前不领取下一个命令。
服务器对 unknown 的 capture 禁止自动重新执行，需检查 SD 或人工处理。

2.4 GET P/time -> 200
{"unix_s":1791972000,"rtc_utc_offset_min":480}
ESP 内部和网络一直使用 UTC；MCU 按 offset 将日历写入 DS3231。
480 是保持当前本地显示语义的建议，不是现有 RTC 时区已确认的结论。
必须验证偏移、2000..2099 日期范围及 RTC 写后回读；仅收帧不代表校时成功。

2.5 照片 API（第二阶段，第一阶段不强行联通）
MCU 对已关闭且不可再变的 SD 文件生成并持久保存 photo_id；
同 ID 永远对应同一组 length/crc32/内容，重启后不能给旧文件换新 ID。
整图 CRC 使用 CRC-32/ISO-HDLC，JSON 为 8 位小写十六进制。
POST P/photos -> 200/201：
  请求 {"photo_id":"<32hex>","name":"IMG0001.BMP","size":691254,
        "crc32":"12345678","content_type":"image/bmp","captured_at":null}
  响应 {"photo_id":"<32hex>","next_offset":0,"complete":false}
  size 只是示例，以 SD 文件实长为准；captured_at 未校时时为 null。
  同 ID/元数据幂等恢复，元数据不一致返回 409；服务端不使用 name 拼磁盘路径。
GET P/photos/{photo_id} -> 200：返回同一上传状态，另含 size、crc32。
PUT P/photos/{photo_id}/chunks/{offset}，Content-Type: application/octet-stream：
  body 为 1..512 字节原始文件内容，最后一块可短；offset 从 0 顺序增长。
  200 返回 {"photo_id":"<32hex>","next_offset":512}，只在该块持久化后返回。
  完全相同 offset/body 重传幂等；冲突或跳跃写返回 409 + expected_offset。
  请求超时后先查询服务端进度；绝不只根据发出字节数推进本地偏移。
POST P/photos/{photo_id}/complete，body={} -> 200：
  服务端从完整文件重新计算 length/CRC 后，原子提交并持久化完成状态，返回
  {"photo_id":"<32hex>","complete":true,"size":691254,"crc32":"12345678"}。
  缺块/校验不符返回 409；重复完成请求幂等。
只有验证 complete=true 且 ID/实长/CRC 全部匹配后，ESP 才发送 UART PHOTO_COMMIT。
CRC 用于传输完整性，HTTPS/设备认证负责来源鉴别。
MCU 持久标记上传成功后应答；原照片仍保留，不自动删除。
ESP/MCU/服务器任意重启均可通过 photo_id + next_offset 恢复；
已完成但 MCU 未记账的照片必须重复取得服务器确认再补 PHOTO_COMMIT。

3. UART 帧提案 v1
物理：USART0，115200，8N1，无流控；TX/RX 与交接文件一致。
仅此链路承载二进制帧，禁止 Serial.print/debug 输出。
ESP 上电 ROM 杂字节视为噪声，MCU 必须重新寻找帧边界。

线编码：0x00 + COBS(raw_frame) + 0x00。
raw_frame 中所有多字节整数为 little-endian：
  offset 0   magic[2]       固定 57 46（ASCII WF）
  offset 2   version u8     1
  offset 3   type u8        消息类型
  offset 4   session u32    ESP 每次建立会话分配非零随机数
  offset 8   seq u32        本次请求序号，响应回显；重传不改变
  offset 12  length u16     payload 长度，0..544
  offset 14  payload[N]
  offset 14+N crc32 u32     对 offset 0..13+N 计算，尾部不参与
CRC-32/ISO-HDLC：反射多项式 EDB88320，init/xorout=FFFFFFFF，
refin/refout=true；ASCII "123456789" 检查值 CBF43926。
raw 最大 562 字节，COBS 编码最大 565 字节，加两端 delimiter 最大 567。
超长帧丢弃到下个 00；帧内字节间超时 250ms 后丢弃局部帧；
magic/version/长度/CRC 不符静默丢弃，不对未知损坏序号发送 NACK。
空帧忽略；连续 delimiter 允许；对端断连后必须重新 HELLO。

3.1 类型与 payload（concat 按以下顺序，无隐式 padding）
0x01 HELLO ESP->MCU：无 payload。
0x81 HELLO_ACK MCU->ESP：mcu_boot_id u32, capabilities u32。
  capability bit0=status，bit1=commands，bit2=rtc，bit3=photos；其他位必须为 0。
  MCU 每次启动改变 boot_id；新会话清除传输层去重，不清除业务命令账本。
  收到重复 HELLO 只重发原应答，不中止正在执行的动作。
0x02 STATUS_REQ ESP->MCU：无 payload。
0x82 STATUS MCU->ESP：exposure u16, gain u16, interval_s u32,
  flags u16（bit0=recording,1=rtc_valid,2=sd_ready,3=busy）, valid_mask u16。
  valid_mask bit0=exposure,1=gain,2=interval,3=recording,4=rtc,5=sd,6=busy。
  未置 valid 位的值必须视为未知；所有保留位发 0。
0x03 COMMAND ESP->MCU：command_id[16], opcode u8, args[变长]。
  opcode 1=capture，无参数；2=set_parameters，exposure u16 + gain u16；
  3=timelapse_start，interval_s u32；4=timelapse_stop，无参数。
0x83 COMMAND_ACK MCU->ESP：command_id[16], status u8。
0x04 RESULT_REQ ESP->MCU：command_id[16]。
0x84 RESULT MCU->ESP：command_id[16], state u8, code u16, photo_id[16]。
  state 0=running,1=succeeded,2=failed,3=unknown；无 photo_id 时 16 字节全零。
  非 capture 的成功结果 photo_id 全零；capture 成功必须有实际 SD 文件 ID。
0x05 TIME_SET ESP->MCU：unix_s u64, rtc_utc_offset_min i16。
0x85 TIME_RESULT MCU->ESP：status u8, verified u8。
  只有完成 DS3231 写后回读且 verified=1 才能报告校时成功。
0x06 PHOTO_NEXT ESP->MCU：无 payload。
0x86 PHOTO_META MCU->ESP：status u8, photo_id[16], size u32, crc32 u32,
  captured_at u64（未知为 0）, name_len u8, name[name_len]。
  name 仅 ASCII 文件名，1..64 字节，不含路径分隔符；无待上传照片 status=6。
0x07 PHOTO_READ ESP->MCU：photo_id[16], offset u32, length u16（1..512）。
0x87 PHOTO_DATA MCU->ESP：photo_id[16], offset u32, data_len u16, data[data_len]。
  最大 payload=534；EOF 不返回伪造空成功块；读取失败回复 ERROR。
0x08 PHOTO_COMMIT ESP->MCU：photo_id[16], size u32, crc32 u32。
0x88 PHOTO_COMMIT_ACK MCU->ESP：photo_id[16], status u8。
0xFF ERROR MCU->ESP：request_type u8, status u8。
status/code：0=OK,1=BUSY,2=BAD_ARGUMENT,3=UNSUPPORTED,4=IO_ERROR,
5=UNKNOWN_ID,6=NO_PHOTO,7=CONFLICT,8=IN_PROGRESS,9=RTC_VERIFY_FAILED。
非 OK PHOTO_META 仅含 status 一字节；其他响应严格按其布局解析。

3.2 应答、重试与流控
仅 ESP 发起请求，MCU 不主动推照片；同一时刻最多一个未应答请求。
ESP 每次发请求前准备接收，不在等待 MCU 响应期间发起 HTTP/TLS。
MCU 每个请求最多发一个有界应答；PHOTO_READ 仅在 ESP 有空闲块缓冲时发出。
seq 从 1 单调递增，回卷前更换会话；错误 session/seq/type 响应丢弃。
普通应答超时 1000ms，最多重试 3 次；TIME_SET 结果超时暂定 5000ms。
MCU 保存最近请求内容与响应；重复的 session/seq/内容重发缓存响应，
同 session/seq 但内容不同返回 CONFLICT，绝不重新执行副作用。
长时间拍照先 COMMAND_ACK，然后 ESP 用 RESULT_REQ 查询，不阻塞等拍照完成。
COMMAND_ACK=OK 只表示命令已接受，不表示执行完成。
TIME_SET 超时仅表示结果未知，不能据此宣称 RTC 未更新；用状态/回读协调。
照片块“接收确认”采用停止等待拉取：匹配的 PHOTO_DATA 为当前 READ 的应答；
ESP 确认/上传当前块后才请求下一 offset，MCU 不主动重发，超时由 ESP 重发 READ。
这避免在 TLS 阻塞期间 MCU 连续发送造成 ESP RX 溢出。

3.3 跨重启去重必须由 MCU 负责人明确落实
UART seq 只解决当前会话重传，不能替代 command_id 的业务去重。
MCU 在执行 capture 前持久记录 command_id 和执行意图，完成后记录结果与 photo_id；
收到同 ID 返回已有状态，不重复拍照。SD 不可用且不能记账时拒绝 capture。
跨重启遇到“已记意图、完成记录未知”标为 unknown，先检查文件，不自动重拍。
MCU RAM/Flash 紧张，具体账本位置、保留时间及断电原子性需负责人评审。
若首版无法提供持久去重，服务器须禁止不确定命令自动重放，且文档明确限制。
