服务器侧接口评审 / v1 实现基线 / 2026-10-14

已阅读 ESP8266_INTERFACE_PROPOSAL.txt v0.1。原对话现在实现 wifi/server/。
以下修改覆盖原提案同名条目；其余 HTTP 路径、字段、CRC 和 UART 布局接受。
这是服务器侧确认；Arduino 对话请阅读后将接受/疑问写入单独状态文件。

1. HTTP v1 与 UART v1
- 接受 /api/v1/devices/{device_id}、Bearer 设备令牌、32 位小写 hex ID。
- 接受 heartbeat / time / commands / photos 所列字段。
- 接受 UART COBS + CRC32、停止等待、512 字节照片块和当前消息类型。
- JSON 上限 2048，原始照片块上限 512；device JSON 响应含 Content-Length，无压缩。
- 接受 exposure 3..5990、gain 16..143、interval_s 2/5/10/30/60。
- RTC 使用 UTC epoch + offset=480，保持用户现有北京时间日历显示。

2. 首版禁止未知命令自动重放（重要修订）
MCU 持久账本尚未实现，不采用提案中的“租约到期后重新领取”。
- queued 命令 expires_at 为创建后 120 秒。
- 首次 GET next：queued -> claimed，分配固定 lease_id，lease_s=120。
- 租约有效的 claimed 重复 GET：返回同一 command_id、lease_id（网络重试）。
  设备必须在同一次运行内按 command_id 去重，不能重复向 MCU 发起新动作。
- 收到 dispatched 事件后 GET next 返回 204；设备继续查询 MCU RESULT 并续租。
- claimed/dispatched 租约到期 -> unknown，禁止自动重新排队。
- queued 过期 -> expired；不再下发。
- 设备 boot_id 改变时，将 claimed/dispatched 标为 unknown，queued 标为 expired。
  首次设备连接没有旧 boot_id 时，不作此判断。
- 事件状态允许 dispatched/succeeded/failed/unknown；同 event_id 同请求幂等。
- dispatched 可续租，不能回退终态；终态后新 event_id 的同终态/同 code/result
  可接受为幂等，冲突内容返回 409；原 lease_id 必须匹配。
- unknown 是终态，晚到执行结果返回 409；不得自动重新执行。
- unknown 之后网页允许用户明确提交新的动作，显示此前结果未知。
- 命令创建与 GET next 都要求近期心跳且 mcu_online=true。
- heartbeat 间隔 30 秒；服务器 90 秒未见设备视为离线。
- 每设备最多一个 queued/claimed/dispatched；事件响应仍为提案字段。
- 设备应在 heartbeat 成功且 MCU HELLO 成功后领取命令。MCU 通信丢失时
  及时报告 mcu_online=false，不能将缓存状态视为当前硬件状态。

3. 照片
- 接受全部 photos API、CRC-32/ISO-HDLC、幂等恢复及 PHOTO_COMMIT 约定。
- 首版仅 image/bmp，size 最大 8MiB；name 仅安全 ASCII 文件名，1..64 字节。
- captured_at 为 UTC epoch 整数或 null；未知时间不能伪装成当前拍摄时间。
- chunks 顺序写，重复块必须落在已写区域内且逐字节相同。
- complete 后验证 BMP 结构（未压缩 24 位）和长度/CRC 才在相册可见。
- 无效图片/整图 CRC 错误需停止并报告，不自动删除 SD 原文件。
- 默认服务端预留配额 2GiB，容量不足返回 507；不自动删除用户照片。

4. HTTP 错误补充
- code/message 采用统一 error 对象；409 偏移冲突时 expected_offset
  放在 error 内，例如 {"error":{"code":"OFFSET_CONFLICT","message":"...","expected_offset":512}}。
- 401/403 认证失败；409 状态冲突；413 超长；422 参数非法；507 存储配额不足。
- 错误 JSON 不含访问密钥。
