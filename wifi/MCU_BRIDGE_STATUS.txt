一、已实现能力
- USART0 115200 8N1，只响应 ESP 请求，无自发日志/推流；HTTPS 期间不会主动发送照片。
- HELLO、STATUS、COMMAND/RESULT、TIME_SET、PHOTO_NEXT/READ/COMMIT。
- HELLO capabilities=0x0f；有状态、命令、RTC、照片能力，运行状态仍需看各响应。
- 曝光 3..5990、gain 16..143，沿用 MCU menu_commit，既有触摸/按键仍可用。
- 拍照异步完成；开始延时摄影成功只表示启用调度，不保证后续每张照片都成功。
- 停止在当前保存安全边界完成，不在 FAT 写入中强制中断。
- USART1 保留原 PC RTC 校时/诊断，USART0 严格二进制。
- FPGA WIF1 能力标识缺失时不初始化 UART0，USART1 提示 FPGA_WIF1_REQUIRED。
- TX/RX 中断、128-byte RX ring；主循环 SD 服务点继续处理串口。
- PHOTO_NEXT 立即返回 BUSY 并调度主循环准备，每轮最多扫描 8 项，后台连续推进；请求本身不执行存储 I/O。
- SD 服务点不重入 FatFs；READ/COMMIT 遇到 SD 服务回调立即返回 BUSY。详见 PHOTO_NEXT_LATENCY_REVIEW.txt。

二、序号与命令去重
- session/seq 均必须非零；新 session 必须先 HELLO；同 session seq 必须递增。
- 仅缓存最近一个传输请求/响应；完全相同 session+seq+body 重试重发缓存，不再执行。
- 相同序号不同内容返回 CONFLICT；过旧序号拒绝。seq 用尽前 ESP 应换 session 并 HELLO。
- CRC 错误/超长帧丢弃并等 00 重新同步；组帧间隔超 250ms 丢弃残帧。
  间隔时间按主循环取字节计时，不是逐字节硬件时间戳；阻塞期间 UART 溢出会报错并重同步。
- 入站编码帧上限 64 bytes；已定义请求 payload 最大 24，全都容纳。
  回复保留完整 payload 544 / 照片块 512 字节，不能据此发送任意 544-byte 请求。
- BUSY 也是缓存响应，后续查询/重试用新 seq；未完成异步请求保持 stop-and-wait。
- 最近 8 条业务命令结果 + 最大已接受 command_id；缓存满可淘汰已终结最旧结果。
- 已缓存 ID 同参数返回原 ACK/RESULT；同 ID 不同参数 CONFLICT。
- 淘汰后 ID <= high-water 返回 UNKNOWN_ID/unknown，绝不重新执行。
- 服务器现已在 SQLite 持久分配严格递增 128-bit command_id，ESP 只需原样转发。
  旧随机 ID 服务端必须升级；详细兼容约束见 MCU_PROTOCOL_ADDENDUM.txt。
- 新 HELLO/session 不清业务账本。MCU 重启会失去 RAM 账本，不承诺跨断电 exactly-once。
  继续严格执行 unknown 禁止自动重放。显式用户新操作是新的 command_id。
- boot_id 用 NOLOAD magic/counter/complement 保留暖复位计数；冷启动用 RTC/timer 种子。
  这是尽力重启标识，不是密码学随机或持久唯一 ID；冷启动重复不能完全排除。

三、时间
- TIME_SET 使用 UTC epoch u64 + offset i16，转换到 2000..2099 本地日历，默认北京 offset=480。
- RTC2 能力检测；与 USART1 PC 校时共用互斥所有权，忙时回复 BUSY。
- 只有 FPGA 写入后回读确认完成、序号更新且无错误，才回复 OK/verified=1。
- RTC 回读失败回复 RTC_VERIFY_FAILED；3.5s 未完成回复 IN_PROGRESS/verified=0。
  超时结果未知，不能理解成没有写入，更不能报成功。
- PHOTO captured_at 来自拍摄时 FAT RTC 时间，UTC 秒；RTC 不可信/越界时为 0（ESP 映射 null）。
  FAT 时间精度为 2 秒；不会将上传时间伪装成拍摄时间。

四、照片持久化与限制
- 完整 BMP 关闭成功后，发布 Txxxxxxx.WFM 元数据，保存固定 photo_id/长度/CRC/时间及元数据 CRC。
- ID 由卷序列号、文件序号、整图 CRC、FAT 时间组成，存于 SD；MCU/ESP 重启不重新生成。
  它不是随机 UUID；复制整张卡会复制身份，不宣称不同克隆卷全球唯一。
- PHOTO_NEXT 只提供带有效元数据的新完成照片；旧 BMP/中途文件不自动上传、不删除。
- PHOTO_READ 1..512 bytes，按 offset 拉取；文件关闭后才发布，整图 CRC 由实际保存字节计算。
- COMMIT 校验 ID/长度/CRC，追加带 CRC 的确认记录，重复提交幂等，永不删除 BMP。
- 掉电仅损坏确认尾部且原元数据仍有效时会再次上传/确认；元数据坏则跳过。
- FAT 不提供整体事务掉电保证；缺卡/I/O 错误如实返回，不能当作已上传。
- 目前仅 640x360、24-bit BMP，691254 字节；无 JPEG、实时视频、历史 BMP 导入或远程刷写。
- 内存受限，SD 临时缓冲由 1536 缩到 768 bytes（像素/分辨率不变），实机保存速度待测。
